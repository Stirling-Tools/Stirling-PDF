How it was measured: four Docker containers ran at the same time on one 16-thread machine, each pinned to its own 4 CPUs with a 6 GB memory cap and a 4 GB server heap, all on Ubuntu 24.04 with Java 25 and the same Stirling-PDF build. Each run is a fresh JVM, with a warm-up round left out, then 3 rounds (1 request) or 2 rounds (4 or 8 requests). Time is the median merge; memory is the peak resident memory of the server process plus any worker processes. PDFBox is PDFMergerUtility with the v2.0.0 size-based scratch cache. "qpdf" variants merge the original files with qpdf outside the PDFium lock, then use PDFium only to add bookmarks back. PR 148 is JPDFium's native-domain branch at its reviewed head 0ff9c36, built locally; it links the system qpdf 11.9 where 1.3.0 bundles its own. With 1 file, JPDFium copies the file unchanged while PDFBox re-saves it. Worker rows were checked to have their workers running.
